# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | Read the branch diff's changed files and substantive hunks against the final plan's scope, implementation steps, and `## Deviations`. Also compare the PR description's claims with the plan and diff. | Passes if the substantive work shown in the diff stays within the plan or an explicitly recorded deviation, and the description accurately represents what the diff demonstrates. A planned item may be deferred without failing when the deferral is explicitly recorded in the plan or deviations and honestly disclosed in the description. Fail for demonstrated silent extra work, silently omitted planned work, or fidelity claims contradicted by the diff. Do not infer silent drift solely from hypothetical or transitive effects on callers or code paths that the package does not show; grade the behavior and changes evidenced in the package. | required |
| Test evidence | Read the candidate's test evidence against the final plan's test plan, original reproduction, and repository-required checks. Use the diff's regression tests as supporting evidence where they directly assert the planned behavior. | Passes if there is specific, observable evidence that the reported bug or behavior was exercised after the change and produced the planned outcome. Before/after evidence, a concrete repro result, or an equivalent bug-specific result may establish this; every secondary check does not need a full raw transcript when its specific result is reported or directly supported by a regression test in the diff. The evidence must also account for material controls or repository checks required by the plan or repo. Fails when evidence is only a generic claim such as "tested locally" or "all tests pass," when only an unrelated/control path was exercised, when the reported failure mode itself was never checked, or when a required repository check is omitted without disclosure. | required |
| Diff quality | Read the complete branch diff against the issue and final plan. Look for debug lines, commented-out experiments, unrelated edits, unnecessary cleanup, formatting churn, dead code, or other changes unrelated to the planned fix. | Passes if the diff is focused and reviewable: its substantive changes contribute to the planned fix or a recorded deviation, and it contains no unrelated changes, leftover debugging, dead experiments, or avoidable churn that obscures the work. | required |
| Standards and comms | Read the PR title and description against the repo-facts block or, in live mode, the repository's PR template, `docs/CONTRIBUTING.md`, issue thread, and stated AI-use or disclosure policy. Check whether the substance of the repository's stated asks is present. | Passes if the PR substantively satisfies the repository requirements that apply to it, such as identifying the issue when required, supplying requested change-type or changelog information, addressing required testing or contribution expectations, and following any stated AI-use disclosure policy. Exact template formatting is not required unless the repository explicitly requires it. Fails when a material stated requirement is omitted or contradicted. Do not invent requirements the repository does not state. | required |

## Verdict rule

Accept only if every required check passes. Reject if any required check fails. Treat `unclear` on a required check as a failure because an unverifiable required condition is not ready to submit. Preferred checks, if any are added later, never change the final verdict.
